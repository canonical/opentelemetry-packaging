# ADR-004: Use `3.0 (quilt)` source format with a pinned orig tarball

Date: 2026-07-02
Status: Accepted

## Context

Debian source packages come in several formats.
Two were relevant here:

**`3.0 (native)`** — the entire source tree is packed as a single tarball.
No separate "upstream" tarball exists.
Version numbers have no `-` revision suffix (e.g. `0.1.0`, not `0.1.0-1`).
Implies that this repository *is* the upstream project, not a packaging layer
on top of one.

**`3.0 (quilt)`** — splits into an orig tarball (upstream source) and a
`debian.tar.xz` (the packaging layer).
Version numbers follow `<upstream>-<debian_revision>` (e.g. `0.1.0-0ubuntu1`).
The `-0ubuntu1` suffix encodes: never packaged in Debian (`-0`), first Ubuntu
packaging revision (`ubuntu1`).
Required for Ubuntu universe.

A third question arose within the quilt approach: **what goes in the orig
tarball?**

Three sub-options were considered:

1. **Stub orig** — a nearly empty tarball containing only a placeholder file.
   Our own files (`scripts/`, `packaging/`, etc.) live alongside `debian/` in
   the packaging layer.
   This was attempted but rejected: `dpkg-source` treats every non-`debian/`
   file not in the orig as a quilt diff patch, causing it to reject the build
   unless every such file is listed in `extend-diff-ignore`.
   That approach is fragile and misleads anyone reading the source package.

2. **Repo snapshot orig** — pack everything except `debian/` as the orig.
   This was our second attempt.
   It works mechanically but is conceptually wrong: the orig is supposed to be
   something that came from upstream, not something we generated ourselves.
   It also created a maintenance burden: the orig must be regenerated every
   time any non-`debian/` file changes.

3. **Real upstream artifacts orig** — the orig tarball contains only the
   pre-built upstream binaries (`upstream/`): the injector `.so` files, the
   Java agent JAR, the Node.js npm bundle, and the .NET assemblies.
   Our own packaging files live entirely inside `debian/`.
   The `upstream/` tree is excluded from the quilt diff via
   `debian/source/options`.

Option 3 was also considered in two flavours:

- **Always-latest**: fetch whatever is newest from GitHub at build time
  (inside `debian/rules`).
  Rejected because it makes builds non-reproducible and requires network
  access on the builder — both prohibited for Ubuntu universe, and bad
  practice even for a PPA.

- **Pinned versions**: versions are fixed in `debian/versions.mk`.
  The orig tarball is generated by `debian/scripts/get-orig-source.sh`, which
  downloads exactly those versions.
  The build has no network dependency and is fully reproducible.

## Decision

Use `3.0 (quilt)` source format.
The orig tarball contains only the pinned upstream binary artifacts under
`upstream/`.
All Canonical-authored content (config files, lifecycle scripts, build rules)
lives entirely inside `debian/`.
Versions are pinned in `debian/versions.mk` and the orig is regenerated by
`debian/scripts/get-orig-source.sh` when versions change.

## Consequences

**Reproducibility**: two builds from the same source package (orig + debian
tarball) produce identical binary packages.

**No network at build time**: `debian/rules` copies files from the unpacked
orig; it does not fetch anything.
This satisfies the Ubuntu buildd constraint and makes local builds fast.

**Explicit version management**: upgrading a component requires a conscious
decision — update `debian/versions.mk`, re-run `get-orig-source.sh`, bump the
changelog, and upload a new source package.
There is no "drift" where the installed package silently changes between builds.

**Orig tarball size**: the orig tarball is approximately 31 MB, dominated by
the .NET managed assemblies and the Node.js bundle.
This is uploaded to Launchpad once per upstream version bump and is cached
there; it does not affect installation size.

**Universe compatibility**: the `3.0 (quilt)` format and the `-0ubuntu1`
version scheme are required for Ubuntu universe.
The remaining blocker for universe is building all components from source
rather than bundling pre-built binaries (see ADR-001).

**`extend-diff-ignore`**: `debian/source/options` excludes `upstream/`,
`README.md`, `LICENSE`, and `.github/` from the quilt diff.
`upstream/` is excluded because it is part of the orig and must not be
patched.
The others are repository metadata that are not part of the quilt diff but
are not in the orig either (they live in the working tree and in the
`debian.tar.xz`).
